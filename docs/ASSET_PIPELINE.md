# 岚汐纪：Houdini 与 Godot 资产工作流

## 当前实际状态

当前可运行版本的主要模型由 `scripts/asset_factory.gd` 生成：四类建筑、四类单位、三类资源，均是本项目原创的组合网格，有独立轮廓、檐口、门窗、柱体、装备和材质分区。模型及地形没有使用其他游戏的素材。Godot 运行时不需要 Houdini、Houdini Engine 或 SideFX 许可证。

已在本机 Godot 4.7.2 中创建全部模型，运行与模拟的同步检查，并用 Apple M5 的实际 OpenGL Compatibility 渲染器检查画面。测试发现并修复了地面绕序、近地层阴影条纹和色调映射过曝。模型细节属于风格化游戏原型级别，尚不是经过手工雕刻、烘焙和专业动画制作的最终商业资产。

`houdini/generate_assets.py` 提供可执行的 Houdini 资产生成入口。当前机器尚未验证 Houdini/hython/许可证；本次只通过了脚本及其嵌入 Python SOP 源码的 Python 语法检查，**未声称 Houdini 已运行或 GLB 已成功导出**。

## 坐标、命名、材质

- 单位：1 Houdini/Godot 单位 = 1 米。
- 方向：+Y 向上，-Z 为单位正面；`Vector2(x,z)` 是模拟坐标。
- 原点：建筑及单位采用地面中心；地形原点为西南角 `(0,0,0)`，面积为 `80 × 80`。
- 游戏地表严格平整，Y=0；视觉模型在运行时放到 Y=0.10，海平面为 Y=-1.68。
- 文件：`{kind}_team{0或1}_lod{0或1或2}.glb`，资源使用 team0。
- SOP 输出：`OUT_LOD0`、`OUT_LOD1`、`OUT_LOD2`、`OUT_COLLISION`；几何保存 `Cd` 顶点色和 `name` 部件属性。
- 贴图若后续引入：PC 主要建筑通常不超过 2048²，手机优先 1024²；颜色贴图使用 sRGB，法线及数据贴图使用线性空间。当前资产无需外部贴图。
- 玻璃晶体以不透明高光/自发光表达为主，避免大量透明物体叠加。

## 在 Houdini 里生成

在安装 Houdini 后，使用该版本自带的 `hython`，不要用系统 Python 替代。以下路径中的 `hython` 需替换为本机实际安装路径：

```bash
/path/to/hython /path/to/lanxi-chronicles/houdini/generate_assets.py \
  --output /path/to/lanxi-chronicles/houdini/generated \
  --seed 42 --size 80
```

脚本在现有场景中创建新的 `lanxi_original_kit` 子网络，不会清空当前场景。每个资产包含保存在 HIP 内部的参数化 Python SOP、法线节点、LOD 输出和简单碰撞输出。它会写入 HIP、BGeo 和 `manifest.json`。相同 `--seed` 与 `--size` 会得到相同几何。

`--size` 控制独立地形的米制边长，`--seed` 控制植被变化。阵营、结构半径和屋顶分段参数保存在各资产的 `PARAMETRIC_SOURCE` 开头，可直接修改后重算。它提供建筑、地形和资源植被；当前单位仍由 Godot 原创网格生成器提供。骨骼、皮肤权重和正式动作需要在后续角色资产阶段制作。

如果该 Houdini 版本包含 glTF ROP SOP，可尝试：

```bash
/path/to/hython /path/to/lanxi-chronicles/houdini/generate_assets.py \
  --output /path/to/lanxi-chronicles/houdini/generated --seed 42 --export-glb
```

脚本会检查已安装的 `rop_gltf` 类型、输出参数、执行入口及文件是否存在。导出器版本或授权不兼容时，会记录清晰错误，同时尽可能保留已生成的场景和 BGeo，不会伪造成功结果。节点参数在 Houdini 大版本间可能变化，需要在实际安装后校验。

手动导出备用路径：打开生成的 HIP，选择某个资产的 `OUT_LOD0`，在 Houdini 的 glTF 导出器中指定该 SOP 路径、静态帧、二进制 GLB 和输出文件。确认顶点色与材质被导出。不要把整个资产展示库一次导出为一个游戏建筑。

SideFX Apprentice、Indie 与商业许可对文件类型、商业使用和部分导出功能具有不同限制。HIP 的最终后缀可能由许可决定为 `.hipnc` 或 `.hiplc`。以实际安装版本和 SideFX 的当前许可条款为准；本脚本不解除授权限制。不要将非商业许可产物未经核查直接用于商业发布。

## Godot 导入与替换

1. 把单个已验证 GLB 放到项目的 `assets/generated/`。
2. 严格遵守文件名，例如 `heart_team0_lod0.glb`、`house_team1_lod0.glb`。
3. 在 Godot 导入面板检查米制尺寸、原点、法线、顶点色和材质；使用“重新导入”。可按资产启用 Godot 自动生成网格 LOD。
4. 运行游戏。`asset_factory.gd` 自动检测同名 `_lod0.glb`；存在有效 3D 场景时加载它，否则继续使用原生原创模型。
5. 检查两个阵营、全部视角、选中圈、血条、建造缩放、最低/最高镜头缩放及手机画质。当前程序单位动画只应用于内置模型；导入角色需要额外接入 `AnimationPlayer`。

地形 GLB 不自动替换游戏地面，因为替换地形须同时校准模拟、点击平面和战争迷雾。`OUT_COLLISION` 用于内容校验或未来物理系统；当前 RTS 使用确定性二维占地和网格寻路，不依赖导入的物理碰撞器。

## LOD、实例化与性能现状

当前运行时共享基础网格和材质，并以 MultiMesh 批量绘制盐草。低、中、高档位分别控制草数量、日光阴影和海面波动。游戏模型没有声称具备完整的自动远近 LOD 切换链；Houdini 输出的 LOD1/2 是后续发布优化接口，使用前须实测减面结果并配置 Godot 导入/可见距离。

应以手机实机的单位规模、绘制调用、帧时间和内存为标准，再决定把每个建筑合并成 1–3 个材质网格、批量实例化军队、减少远处动画和贴图规格。不能把桌面截图当成手机性能测试。
